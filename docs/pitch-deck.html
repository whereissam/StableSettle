09 — How the cap works

The limit is five lines of Solidity.

There's no “Arc spending limit” feature — the cap is a contract we wrote. USDC lives in AgentVault; the agent only holds a role; every spend runs this gate before any money moves.

// only the agent's ROLE may call — it never holds the funds
function spend(to, amount) onlyRole(AGENT_ROLE) {
  require(amount <= maxPerSpend) // per-transaction cap
  require(spent + amount <= budgetCap) // ← THE LIMIT
  require(amount <= dailyRemaining()) // rolling 24h velocity
  spent += amount // recorded BEFORE money moves
  USDC.transfer(to, amount) // …only now does it pay
}
// over ANY limit → revert. no backend, no co-signer, no off-chain gate.

The money lives in the contract; the agent can only ask. A stolen key, a hallucination, a prompt injection — all hit the same wall: spend() reverts.

15 — How to drive it

Set the caps. Top up. All by name.

MCP tools — call in Claude
spawn_agent name=trader budget=5000 maxPerSpend=500 fund=1000 gas=1
# ↑ one call: lifetime cap + per-tx cap + initial funds + gas
fund_agent  name=trader amount=500   # top up the treasury (spendable USDC)
topup_gas   name=trader amount=1     # top up the agent's gas (USDC is gas on Arc)
get_agent   name=trader          # cap · spent · remaining · per-tx · daily · balance
Owner controls — your wallet, on-chain (anytime)
setCap(newCap)        # raise / lower the lifetime budget
setMaxPerSpend(limit)   # the per-transaction cap
setDailyLimit(limit)   # rolling 24h velocity cap
revoke() / withdraw(to,amt) # freeze the agent / pull funds out

Every limit is an owner-only on-chain call — the agent can spend, but only the human can change what it's allowed to do. The MCP tools are the easy path; the contract is the source of truth.
